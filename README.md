# MyFitnessPal — Резюме бізнес-плану

## Технічний стан MVP (вебзастосунок)

### Запуск

```bash
python3 backend.py
```

Після запуску відкрийте: `http://127.0.0.1:4173`

### Де зберігаються акаунти (логін/пароль)

- База даних: **SQLite**
- Файл за замовчуванням: **`/workspace/myfitnesspal.db`**
- Таблиця користувачів: `users`
- Паролі не зберігаються у відкритому вигляді (salt + SHA-256 hash).

Можна перевизначити шлях до БД через змінну середовища:

```bash
export MYFITNESSPAL_DB_PATH="/workspace/myfitnesspal.db"
```

### Реальні джерела AI/food-даних

- **Розпізнавання їжі (AI):**
  - OpenAI Vision (якщо задано `OPENAI_API_KEY`)
  - Clarifai Food Model (якщо задано `CLARIFAI_PAT`)
  - fallback: MobileNet
- **Харчова база/нутрієнти:**
  - Edamam Food Database (`EDAMAM_APP_ID`, `EDAMAM_APP_KEY`) — пріоритетний пошук з урахуванням грамажу порції
  - USDA FoodData Central (`USDA_API_KEY`)
  - FatSecret (`FATSECRET_CLIENT_ID`, `FATSECRET_CLIENT_SECRET`)
  - OpenFoodFacts (безкоштовний fallback)

### Firebase Authentication

Фронтенд використовує Firebase Auth (email/password), а бекенд приймає Firebase ID Token через:

- `POST /api/auth/firebase`

На клієнті потрібно задати:

1. Відкрийте файл `firebase-config.js`.
2. Заповніть поля:

```js
window.MYFITNESSPAL_FIREBASE_CONFIG = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  appId: "YOUR_APP_ID"
};
```

На сервері потрібно задати:

```bash
export FIREBASE_PROJECT_ID="YOUR_PROJECT_ID"
```

Якщо Firebase config не заданий, клієнт автоматично використовує локальну авторизацію бекенду (`/api/auth/register`, `/api/auth/login`) як fallback.

Після завантаження фото є окрема кнопка **«Запустити процес»**, яка стартує AI-аналіз.

### Додаткові ключі для точнішого розпізнавання та порцій

```bash
export OPENAI_API_KEY="YOUR_OPENAI_API_KEY"
export OPENAI_VISION_MODEL="gpt-4o-mini"
export EDAMAM_APP_ID="YOUR_EDAMAM_APP_ID"

```

## 2) Резюме бізнес-плану

### Назва проєкту (компанії)
**MyFitnessPal** — вебзастосунок для підрахунку калорій за фото їжі з AI-обробкою зображень.

### Мета проєкту
Створити інструмент для контролю харчування, який за допомогою штучного інтелекту:
- розпізнає страви на фото;
- оцінює вагу/об’єм порції;
- автоматично розраховує КБЖВ (калорії, білки, жири, вуглеводи).

### Опис продукту
PWA-вебзастосунок з інтегрованим AI-модулем комп’ютерного зору для:
- ідентифікації продуктів та інгредієнтів на фото;
- розрахунку калорійності і нутрієнтного складу;
- збереження історії харчування та персоналізованих рекомендацій.

### Застосування продукту
- щоденний моніторинг раціону;
- зниження/контроль ваги;
- набір м’язової маси (спортсмени);
- медичний контроль харчування (наприклад, при діабеті чи гастриті);
- спрощення роботи дієтологів і фітнес-тренерів.

### Ринки збуту
- **B2C:** масовий ринок користувачів смартфонів в Україні;  
- **Масштабування:** країни ЄС і США;  
- **B2B:** фітнес-мережі, медичні заклади, партнерські платформи.

### Потреба в інвестиціях
Початкове фінансування потрібне для:
- розробки MVP і навчання моделі;
- хмарної інфраструктури;
- маркетингу та залучення перших користувачів.  
**Точний обсяг інвестицій:** уточнюється за результатами деталізованої фінмоделі.

## 3) Опис компанії

### 3.1 Місія
Автоматизувати контроль харчування за допомогою AI для людей, які:
- прагнуть знизити або контролювати вагу;
- мають медичні обмеження в харчуванні;
- хочуть економити час на веденні харчового щоденника.

### 3.2 Бачення (3–5 років)
Стати провідним HealthTech-продуктом у Східній Європі з подальшою експансією на ринок США та трансформуватися з «калькулятора калорій» у персоналізовану екосистему харчування з базою понад 500 тис. активних користувачів.

### 3.3 Стратегічні цілі
1. **Рік 1:** запуск MVP, точність розпізнавання до 90%, залучення перших 10 000 користувачів.  
2. **Рік 2:** запуск преміум-підписки, досягнення точки беззбитковості.  
3. **Рік 3:** інтеграція з медичними системами та сервісами доставки їжі, вихід на міжнародні ринки.

### 3.4 Основні групи продуктів / послуг
1. **Базова версія:** AI-розпізнавання страв та підрахунок калорій.  
2. **Розширена версія:** аналітика мікроелементів, персональні рекомендації.  
3. **B2B API:** доступ до AI-технології розпізнавання їжі для сторонніх розробників.

### 3.5 Принципи розвитку
- **Ринкова доцільність:** вирішення реальної та регулярної проблеми користувача.  
- **MVP-підхід:** швидка перевірка гіпотези з мінімальними стартовими витратами.  
- **Захист даних:** дотримання стандартів безпеки персональних і медичних даних.

### 3.6 Стратегічні партнери
- фітнес-клуби (канал залучення клієнтів);
- асоціації дієтологів (валідація методологій);
- сервіси доставки їжі (інтеграції та партнерства).

- ML-інженери та Data Scientists;

### Висновок по галузі
Проєкт виходить на ринок у сприятливий момент перетину двох швидкозростаючих напрямів: **HealthTech + AI**. Рішення закриває ключову потребу в автоматизації та економії часу порівняно з ручним введенням даних.

## 5) Продукт і ціннісна пропозиція

### Назва продукту
Вебдодаток для автоматизованого підрахунку калорій за фото страв із використанням AI.

### Основні споживчі характеристики
- миттєве розпізнавання страв та інгредієнтів за фото;
- автоматичний розрахунок КБЖВ без ручного введення;
- персоналізовані рекомендації за історією користувача;
- зручний інтерфейс для відстеження прогресу.

### Технологія
Комп’ютерний зір + моделі машинного навчання + хмарна обробка + інтеграції із зовнішніми food API.

### Цільовий споживач
Люди, які слідкують за здоров’ям, прагнуть схуднення/набору маси, а також спортсмени та користувачі, яким важлива економія часу.

### Конкурентні переваги
- **Швидкість:** мінімум ручних дій.  
- **Технологічність:** AI-замість ручного пошуку у довідниках.  
- **Зручність:** усунення потреби постійно зважувати і вводити продукти вручну.
